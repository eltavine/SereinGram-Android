# Advertising rules

Open **Settings → SereinGram → Ad blocking**. Rules are per account and evaluated
on the device. Enable blocking to hide matches in groups/channels and suppress
matching new notifications. Private chats, outgoing messages and service messages
are excluded. Messages remain in Telegram history; unread counts are not rewritten.

The built-in rules match explicit advertising labels at the start of a message:
`【广告】`, `【推广】`, `[广告]`, `[推广]`. Long-press a message to **Mark as advertising**,
then hide that message, identical text in that chat, or messages from that user
in that chat. Marking enables blocking. Sender-wide marking is offered only for
user senders, not an entire channel masquerading as a sender.

**Blocking history** retains the latest 500 distinct matched messages, with their
rule, source, timestamp and a short preview. Tap a record to restore and open its
message. Up to 1000 restored-message exceptions are retained; clearing history
does not clear these exceptions. Rules can be inspected and removed on **Manage
rules**. Albums are hidden together if one member matches.

## Subscriptions

The recommended source is [HaGeZi Pop-Up Ads](https://github.com/hagezi/dns-blocklists#popupads),
licensed under GPL-3.0. Its domain-only feed is:

```
https://raw.githubusercontent.com/hagezi/dns-blocklists/main/wildcard/popupads-onlydomains.txt
```

Use **Update subscription now** to download it. Updates are manual. A custom HTTPS
direct URL can return the JSON format below or one domain per line (`#`/`!` comments
and leading `*.` are accepted). Redirects, URL credentials, and fragments are not
accepted. Downloads time out after 30 seconds and are limited to 4 MiB. An invalid
or failed update keeps the last valid list; no message text is uploaded.

This is a link-domain filter, not a DNS/VPN filter or a general advertising
classifier. Browser/Adblock Plus filters and arbitrary regular expressions are
not accepted. Telegram chat sponsored messages are already disabled upstream;
enabling this feature additionally suppresses search and video sponsored ads.
Unfetched sponsored ads are not counted as blocked chat messages.

## JSON version 1

```json
{
  "version": 1,
  "name": "My advertising rules",
  "rules": [
    {"id": "label", "label": "Explicit ad", "kind": "prefix", "value": "[AD]"},
    {"id": "link", "label": "Advertising domain", "kind": "domain", "value": "ads.example"},
    {"id": "one-message", "label": "One message", "kind": "message", "value": "123", "dialog_id": "-1001234567890"}
  ],
  "domains": ["ads.example"]
}
```

| Kind | Value |
| --- | --- |
| `prefix` | Message starts with this literal text |
| `contains` | Message contains this literal text |
| `domain` | A URL uses this domain or a subdomain, including hidden-link entities |
| `sender` | Decimal user/channel ID as a string |
| `message` | Positive message ID as a string; requires `dialog_id` |
| `text_hash` | SHA-256 of normalized text, generated by manual marking |

`dialog_id` is optional for other rule kinds and must be a negative group/channel
dialog ID. IDs are strings to preserve 64-bit precision. Text is normalized using
Unicode NFKC, lowercase and collapsed whitespace. Rule IDs must be unique within
a list. Limits: 2000 personal/imported rules, 150000 domains per list, 512 characters
per rule value. Domain matching respects label boundaries and does not match a
domain merely mentioned inside another URL path.

Import replaces the imported list while retaining manually marked rules. Export
includes personal and imported rules; downloaded subscription lists and blocking
history are not exported. Settings backup covers the switches and subscription URL;
use rule export to back up personal rules separately.
